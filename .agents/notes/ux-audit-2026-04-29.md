# Officehours UX/UI Audit — 2026-04-29

Branch: `feat/ui-expose`. Reference codebases: cal.com (primary, same domain), dub.co (secondary, UI craft).

## TL;DR

Public surface (`/h/[handle]`, booked confirmation, invitation accept) is the most cohesive part of the product — billboard-scale typography, single-shell layout, brutalist palette intact. The host shell, settings hub, and workspaces hub are also internally consistent. The two largest drift zones are **`/login` and `/register`** (still ship a generic shadcn aesthetic — `text-muted-foreground` everywhere, shadcn `Input` with no brutalist treatment, no password reveal, no error parity with cal.com), and **the workspace event-types surface** (hardcoded English, mid-dot separators, `"Loading…"` paragraphs that don't match the SSR-prefetch pattern used everywhere else). The third theme is missing **`loading.tsx`** route segments — Next App Router can stream skeletons during SSR navigation but the project has zero of them, so every page-to-page transition holds the previous frame for the full data round-trip. Mobile-first is honored at the page level (`BrutalistPageShell` + `ResponsiveModal` + drawer swap at 768px), with three concrete exceptions called out below.

## How to read this audit

Each finding follows: ❌ what's wrong now → ✅ what cal.com / dub do → 🔧 the fix. File paths are absolute, line numbers are inline. Skip sections marked "✅ matches reference" — they're flagged so you know they were checked, not glossed over.

The shadcn `<Sidebar collapsible="icon">` does ship a Sheet for mobile, but `BrutalistDashboardLayout` doesn't render a `SidebarTrigger` outside the sidebar so the user has no way to open it on phones. ✅ cal.com Shell renders a hamburger in the topbar at `<md` that toggles the sidebar sheet. dub does the same via `app-sidebar-nav.tsx`. 🔧 Add a `<SidebarTrigger>` to `brutalist-dashboard-bar.tsx` rendered only at `<md` (the existing `src/components/brutalist/topbar.tsx:17` already has the brutalist-styled trigger — wire it into the bar).

✅ Active state (left 2px ink accent + tint bg, font-bold), focus ring (`focus-visible:outline-2 outline-bru-ink`), the `useMounted` deferral for active path (commit-traceable hydration fix) — all correct.

✅ The view-transition wiring (separate `bru-host-content` static frame vs `bru-host-content-inner` snapshot target) is sophisticated and matches the documented intent.
